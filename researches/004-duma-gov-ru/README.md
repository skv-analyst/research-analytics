# duma-gov-ru

Сбор результатов открытых голосований Государственной Думы 8-го созыва (2021–2026) через
официальный API (`api.duma.gov.ru`) в локальную SQLite. Справочные страницы API, на основе
которых написан клиент, сохранены в `api/`.

## Локальная настройка

```bash
uv sync
```

Ключи API — только для этого проекта, не общие для репозитория, поэтому берутся из
локального `.env`, а не из корневого `config.py`:

```bash
cp .env.example .env
```

Заполнить `DUMA_API_KEY` и `DUMA_APP_KEY` значениями с http://api.duma.gov.ru/key-request
(нужен режим «приложение» — оба ключа сразу, т.к. запросы идут не с веб-страницы, и
Referer-проверка для обычного ключа не пройдёт).

## Запуск сбора

Все стадии идемпотентны и резюмируемы — прерванный на середине прогон можно просто
перезапустить, он продолжит с необработанных голосований/депутатов, а не начнёт заново.
Запускать стадии по отдельности через `--stage` (порядок важен — каждая следующая опирается
на данные предыдущей).

**Важно**: параметр `convocation` в `voteSearch` на живом API не фильтрует ничего (проверено —
и с полным id периода, и с голым номером созыва возвращается одна и та же неотфильтрованная
`totalCount` по всей истории с 1994 года). Поэтому скоуп на конкретный созыв делается через
диапазон дат (`from`/`to`), который берётся из таблицы `periods` — отсюда шаг 1 обязателен
перед шагом 2.

### 1. Справочник созывов

```bash
uv run python -m duma_gov_ru --stage periods
```

Один дешёвый запрос, заполняет таблицу `periods` (id, номер созыва, даты начала/конца) —
8 строк, 8-й созыв: `2021-10-12` — `2026-12-21`.

### 2. Список голосований

Сначала — **малая выборка**, чтобы проверить, что всё работает, не пылесося всю историю:

```bash
uv run python -m duma_gov_ru --stage votes --convocation 8 --limit 50
```

Затем — **весь созыв** (`--convocation` берёт диапазон дат из `periods`, `--limit` просто
убираем):

```bash
uv run python -m duma_gov_ru --stage votes --convocation 8
```

~167 постраничных запросов, заполняет `votes` базовыми полями (тема, дата, итог, счётчики).
Без `--convocation` (и без `--limit`) стадия заберёт вообще всю историю голосований —
осознанно так не делать, если не нужен весь массив с 1994 года.

### 3. Детали по каждому голосованию

Самая долгая стадия — по одному запросу `vote/:id` на голосование. Сначала малая выборка:

```bash
uv run python -m duma_gov_ru --stage details --detail-limit 200
```

Затем — все оставшиеся (для 8-го созыва это ~16-17k запросов, при задержке между запросами
уйдёт от получаса до пары часов; в лимит 50k запросов/сутки укладывается с запасом):

```bash
uv run python -m duma_gov_ru --stage details
```

Дополняет `votes` (номер закона, ссылка на стенограмму, ссылка на СОЗД) и заполняет
`votes_by_faction` / `votes_by_deputy`.

### 4. Депутаты

```bash
uv run python -m duma_gov_ru --stage deputies
```

`deputy.json` для каждого депутата, встретившегося в `votes_by_deputy` без биографических
данных (фракция, регион, комитеты, образование) — по одному запросу на депутата, для одного
созыва это ~450 запросов, быстро.

### Проверить прогресс между шагами

```bash
uv run python -c "
from duma_gov_ru import config
import sqlite3
conn = sqlite3.connect(config.DB_PATH)
print('votes:', conn.execute('SELECT COUNT(*) FROM votes').fetchone())
print('with details:', conn.execute('SELECT COUNT(*) FROM votes WHERE fetched_detail_at IS NOT NULL').fetchone())
print('deputies:', conn.execute('SELECT COUNT(*) FROM deputies').fetchone())
"
```

## Схема БД (`duma_gov_ru.db`)

- `periods` — справочник созывов (id, номер, название, даты начала/конца)
- `votes` — одна строка = одно голосование (тема, `law_number`, дата, итог, счётчики,
  ссылка на стенограмму, `sozd_url`)
- `votes_by_faction` — голосование × фракция (счётчики за/против/воздержался/не голосовал)
- `votes_by_deputy` — голосование × депутат (его результат и код фракции **на момент этого
  конкретного голосования** — так фиксируются смены фракции внутри созыва)
- `deputies` — справочник депутатов (ФИО, фракция, регион, комитеты, образование и т.д.)

`sozd_url` строится из `law_number` по известному публичному паттерну
`sozd.duma.gov.ru/bill/{law_number}` — отдельного запроса к API для этой ссылки не нужно.

Ярлыки на законопроекты (влияние на гражданина и т.п.) — постобработка поверх `votes`/
`law_number`, в сборщик не входит.
